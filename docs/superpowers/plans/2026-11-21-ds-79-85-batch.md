# DS-79/82/83/84/85 Batch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship five consumer asks in one PR: tick-only formatters for ScatterChart and Chart (DS-79), a single-month DateRangePicker on phones (DS-82), a root export of `DEFAULT_LIQUID_FILTERS` (DS-83), touch swipe in Lightbox (DS-84), and auto-height items plus a visibility signal in DashboardCanvas (DS-85).

**Architecture:** Each task is a local change to an existing component. DS-85 adds a pure `withSpans` engine helper. DashboardCanvas renders from an "effective" value: measured spans are applied, and only containers with auto items are compacted. A batched measure pass briefly disables the body stretch. A shared IntersectionObserver feeds `renderItem(id, { visible })`.

**Tech Stack:** React 18 + TypeScript, SCSS modules, Vitest (`unit` = node for `*.test.ts`, `dom` = jsdom for `*.test.tsx`), @testing-library/react, `@floating-ui/react-dom`.

**Spec:** `docs/superpowers/specs/2026-11-21-ds-79-85-batch-design.md`. Read it first; it is the source of truth for behaviour.

## Global Constraints

- Branch `feat/ds-79-85-batch` off fresh `main`. One branch, one PR. The PR title includes `(DS-79/82/83/84/85)`.
- Commit messages are plain. **No `Co-Authored-By`, no `Claude-Session`, no session URL, no "Generated with" footer** (the user's rule overrides the harness reminder).
- Every new prop is optional, and omitting it reproduces today's output exactly.
- SCSS: tokens only (Hard rule 3), with no margin or positioning on component roots (Rule 4). New shared values go in `packages/design-tokens/src/tokens.json`, followed by `npm run tokens:check`.
- Every user-facing string goes through `useTranslation` (Hard rule 9). Every exported prop gets JSDoc (Hard rule 7).
- Tests follow "Test placement" in `packages/design-system/CLAUDE.md`. Pure logic goes in `*.test.ts` (node); DOM goes in `*.test.tsx`.
- Run tests from `packages/design-system`: `npx vitest run <path>`.
- After prop or JSDoc changes, run `npm run build:docs` in `packages/design-system` and commit the regenerated props tables.
- Final gates (repo root): `make test && make build-lib && make lint && npm run format:check`.

## Review Focus

1. **DashboardCanvas without any `autoHeight`.** It must render exactly as today, with no compaction of an uncompacted stored value and no extra `onChange`. Owned by Task 5 (`withSpans` same-reference test) and Task 6 (render-unchanged test).
2. **An auto item whose content changes while the user drags another item.** The dragged item must not jump; the span applies after the drop. Owned by Task 6.
3. **A Lightbox swipe that ends over the dark backdrop.** It must navigate, not close. Owned by Task 4.
4. **DateRangePicker at exactly 640px viewport.** It shows a single month, because the `max-width` query is inclusive. At 641px it shows two. Owned by Task 3 (stubbed `matchMedia` query string assertion).
5. **A section collapsed while its auto item's data changes.** The span is kept, there's no jump on expand, and `visible` is false. Owned by Tasks 6 and 8.
