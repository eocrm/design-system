# DS-35 bug batch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix 19 consumer-reported bugs in `@eocrm/design-system`. Most give components ≥44px touch targets and iOS-safe text on coarse pointers. Also add `Chart curve`.

**Architecture:**

- One new primitive token `--size-touch` and one mixin `touch-hit-area`.
- Each component owns a `@media (pointer: coarse)` block in its `*.tokens.scss` that re-points its own size tokens.
- Standalone bugs are fixed in place.
- Real-browser regressions go in a new Playwright `touch` project. It runs inside the existing `npm run test:focus-geometry` CI step, so no workflow change is needed.

**Tech Stack:** React 18, TypeScript, SCSS modules + design tokens (`packages/design-tokens`), Vitest (unit = Node `*.test.ts`, dom = jsdom `*.test.tsx`), Playwright (root `playwright.config.ts`, specs in `tests/`).

**Spec:** `docs/superpowers/specs/2026-11-07-ds35-bug-batch-design.md`. Read it fully; its "Builder-facing calls" table is binding. Each bug's repro is in its eocrm task body. Read it with the eocrm MCP `tasks_get` (workspace `dpws`). Where a task body and the spec disagree, the spec wins.

## Global Constraints

- **Desktop / fine pointer must be pixel-identical.** Every size change lives inside `@media (pointer: coarse)`.
- **New primitive token:** `--size-touch: 44px`, defined in `packages/design-tokens/src/tokens.json` under the existing `size` group.
  - Regenerate the tokens and run `npm run tokens:check` from the repo root.
  - Never edit generated files.
- **iOS 16px text:** coarse-pointer text-entry font is `var(--font-size-lg)` (16px), for every size including `sm`.
- **Rule 4:** components still may not use `margin`, `position` other than `relative`, `top/left/right/bottom`, `flex: 1`, `flex-grow`, `align-self`, `width` other than 100%/auto, or `grid-column/row`. The single exception is the `touch-hit-area` mixin in `src/styles/mixins.scss`.
- **Rules 3, 7 and 9:** tokens only, no raw values. JSDoc on every new prop. i18n for any user-facing string.
- **Docs:** update every touched component's `packages/design-system/docs/components/<Name>.md`, then run `npm run build:docs` from `packages/design-system`, and commit the generated output, including `packages/playground/src/lib/props.manifest.json` when it changes.
- **Playground demos:** a touched component's demo shows the new behaviour where it's visible (props, the Header part, curve).
- **Test placement:** see `packages/design-system/CLAUDE.md`.
  - Coarse-pointer CSS is asserted by reading the SCSS text, following the existing convention in `DashboardWidget.test.tsx:263`.
  - Layout and gesture behaviour goes in Playwright `tests/touch-*.spec.ts`.
- **Commits:** plain conventional commits. No Co-Authored-By, no session links, no "Generated with" footer. Never `--no-verify`. Implementers commit but do not push.
- **Release:** patch (no `release.yml` change).

## Review Focus

1. **Desktop regression.** On Desktop Chrome, Button md is still 32px tall and Input md is still 32px. Owner: Task 2, Playwright `tests/touch-desktop-unchanged.spec.ts` in the `chromium` project.
2. **Chip × hit area swallowing the chip's own action.** On touch, tapping the centre of a FilterChip's label must not fire `onDismiss`. Owner: Task 4, Playwright.
3. **Long-press on an interactive child.** In edit mode on touch, a quick tap on a button inside a canvas item fires that button and does not arm a drag. Owner: Task 6, Playwright.
4. **Nested themes.** Light inside dark inside light resolves the innermost theme's `--color-accent` for every accent. Owner: Task 7, unit test on the generated CSS.
5. **RTL hit area.** In `dir="rtl"`, the hit area of an xs icon button is still centred on the button. Owner: Task 2, Playwright.
