## User rulings

- **#692:** a new `DashboardWidget variant="stats"`: compact header (as `kpi`/`chart`: compact padding, no divider, small muted title) + compact body padding (`--dashboard-widget-compact-padding`). The body still **scrolls on real overflow** (it is a `Card.Body scroll` with `role="group"`, like `standard`). StatTile itself is NOT changed.

No dedicated StickyBar component.
- **Extra (no issue):** the edit-mode snap-grid dots should be subtler: `--dashboard-canvas-dot-color: var(--color-border-strong)`, size stays `1.5px` (#354: a 1px border-strong dot was invisible, so the size stays).
- **#696 interpretation:** the trailing drop space appears **only during an active pointer move-drag** (edit mode only, so it's never present in readOnly/narrow), sized to the dragged item's `h` rows. Content above never shifts, and idle edit mode has no blank band.

## Review Focus

1. **#694 hysteresis:** the hit test uses the _original_ `value` positions (not the preview layout), so the preview can't oscillate as items shift under a stationary pointer. A test pins a stable result for a pointer that stays over the lower half of the upper widget.
2. **#694 dragged item wider than the hovered item / hovered near the right edge:** x is `min(t.x, columns - w)`, floored at 0, so it never straddles past the grid (tested).
3. **#694 pointer over empty cells or over the dragged item's own original rect** → falls back to the existing origin-snapped cell (tested).
4. **#697 interactive steps and `modal={false}`** must NOT get the inert marker (tested). Otherwise the click-to-continue steps break.
5. **#695 ghost larger than the canvas** (a tall widget dragged in a short canvas): the clamp must not produce negative/NaN offsets. Floor at 0 (tested via the pure clamp).

### Task 1: #694 — `insertionCell` engine function

**Files:**

- Modify: `packages/design-system/src/components/DashboardCanvas/engine.ts` (add after `cellFromPoint`)
- Test: `packages/design-system/src/components/DashboardCanvas/engine.test.ts`

**Interfaces:**

- Produces: `export function insertionCell(items: readonly DashboardPlacement[], id: string | number, w: number, px: number, py: number, fallback: { x: number; y: number }, columns: number = DASHBOARD_COLUMNS): { x: number; y: number }`. `px`/`py` are the POINTER position in **fractional cell units** relative to the container (column pitch / row pitch, so `px = (clientX - rect.left) / (colWidth + gap)`).

Algorithm: find the first item `t` with `t.id !== id` and `t.x <= px < t.x + t.w && t.y <= py < t.y + t.h`. If there's none, return `fallback`. Otherwise `x = max(0, min(t.x, columns - w))` and `y = py < t.y + t.h / 2 ? t.y : t.y + t.h`. JSDoc: explain the upper half = insert before, lower half = insert after, and why the caller passes the original value (no hysteresis loop).
