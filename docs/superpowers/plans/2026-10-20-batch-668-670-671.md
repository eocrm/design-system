# Batch #668 / #670 / #671 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the OptionsPicker page scrollbar (#670), add an ancestor-chain highlight to TreeView (#671), and add a content-driven one-row ⇄ stacked mode to Cluster (#668).

**Architecture:** Three independent tasks on branch `fix/batch-668-670-671`. #670 is a one-line containing-block fix in Checkbox/Radio plus a Playwright regression spec. #671 adds a `highlightedIds` prop, CSS for list/chart, and a measured horizontal connector segment in chart view. #668 adds a `stretchWrapped` boolean to Cluster implemented with a `::before` slack spacer.

**Tech Stack:** React 19 + TS, SCSS modules, Vitest (jsdom), Playwright (`tests/`).

**Spec:** the design approved in chat on 2026-10-20, restated here (no separate spec doc):

- **#670** — root cause: `.checkbox` / `.radio` roots are not positioned, so the visually-hidden `position: absolute` native input's containing block is the popover panel; a scroller clips only absolute descendants whose containing block is inside it, so off-scroll inputs extend the document. Fix: `position: relative` on `.checkbox` and `.radio` (Rule 4 allows `relative` as an internal anchor). Regression: Playwright spec on `/components/options-picker`.
- **#671** — `highlightedIds?: ReadonlySet<string>` on `TreeView`. Visual only (no ARIA, no effect on selection/focus). Tokens `--tree-view-highlight-color: var(--color-accent)`, `--tree-view-highlight-width: var(--border-width-emphasis)`. List view: accent inline-start edge on highlighted rows via inset `box-shadow` (no layout shift). Chart view: highlighted box border = highlight color; where a parent and ≥1 of its children are highlighted, the parent's drop (`.group::before`), each highlighted child's stub, and the horizontal segment from parent centre to the farthest highlighted child centre are painted in the highlight color. The segment is measured (layout effect + `ResizeObserver`) using physical left/width (RTL-safe). Ids not rendered are ignored.
- **#668** — `stretchWrapped?: boolean` on `Cluster`. On a shared line, no child stretches and the slack goes to an invisible `::before` spacer between the first child and the rest; any non-first child alone on a wrapped line stretches to fill it (children wrapped together share it). `justify` is inert while on; a consumer `order` on children breaks it (anti-pattern). Canonical: status pill + `<Grid columns={2}>` of buttons. Browser-verified CSS:
  ```scss
  .stretchWrapped {
    &::before {
      content: '';
      flex: 999 1 0;
    }
    > :first-child {
      order: -1;
    }
    > :not(:first-child) {
      flex: 1 1 auto;
    }
  }
  ```

## Global Constraints

- Tokens only in `.module.scss`; new component tokens go in `<Name>.tokens.scss` defaulting to primitives.
- Hard rule 7: every new prop has JSDoc; component docs `packages/design-system/docs/components/<Name>.md` updated and `npm run build:docs` run from `packages/design-system`.
- Tests: Vitest globals (no imports of `describe/it/expect/vi`); jsdom cannot do layout — layout-only facts go to Playwright in `tests/`.
- Playground imports only from `@eocrm/design-system`.
- Run tests from the package dir: `cd packages/design-system && npx vitest run <path>`.
- Commits: plain messages, no Co-Authored-By / session trailers.

## Review Focus

1. TreeView chart: parent highlighted but no highlighted child rendered (collapsed / not loaded) → no accent connector drawn below it. Test in Task 2.
2. TreeView chart: `highlightedIds` changes or the chart resizes → segment re-measured (no stale vars). Test in Task 2 (rerender with a different set).
3. TreeView list: highlighted + selected row keeps the selected background and still shows the accent edge. Test in Task 2 (both attributes present).
4. Cluster `stretchWrapped` with a single child → nothing breaks (first child is never stretched). Covered by CSS; class-application test in Task 3.
5. Radio inside a scroller leaks the same way as Checkbox → same fix; Playwright asserts checkbox only (demo has no scrolling radios), Radio is covered by identical CSS.
