# DiffView Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `DiffView`, a component that renders a unified text diff (DS-94).

**Architecture:** A pure `parseUnifiedDiff` module (Node-tested) feeds a `forwardRef` component that renders a semantic table inside a CodeBlock-like frame. Then the full new-component checklist: docs, manifest and playground.

**Tech Stack:** React 19 + TypeScript, SCSS modules + component tokens, Vitest (unit = Node `.test.ts`, dom = jsdom `.test.tsx`), the library's i18n.

**Spec:** `docs/superpowers/specs/2026-11-25-diffview-design.md`

## Global Constraints

- Props, verbatim: `diff: string; fromLabel?: string; toLabel?: string; lineNumbers?: boolean (default true); wrap?: boolean (default true); maxHeight?: 'xs'|'sm'|'md'|'lg'|'xl'`, plus `HTMLAttributes<HTMLDivElement>` spread on the root, `forwardRef` to the root.
- Package Hard rules (`packages/design-system/CLAUDE.md`):
  - tokens only, via a new `DiffView.tokens.scss` (diff tints default to `--color-success-bg-subtle` / `--color-danger-bg-subtle`, signs to `--color-success-fg` / `--color-danger-fg`, the surface to the `--code-block-*` tokens);
  - no layout properties;
  - JSDoc on every exported member, with the component JSDoc a one-line summary + `@see docs/components/DiffView.md`;
  - every string through i18n, en + ru.
- Change type is never conveyed by colour alone: there is a visible `+` / `−` sign, plus `VisuallyHidden` "Added" / "Removed".

## Review Focus

- A diff with only file headers, or an empty string → empty state, no table → Task 2 test.
- `@@ -0,0 +1,3 @@` (a new file) and `@@ -5 +5 @@` (counts omitted) → correct numbering → Task 1 test.
- CRLF input and a trailing newline → no phantom empty line → Task 1 test.
- `\ No newline at end of file` → a note row, not an added or removed line → Task 1 + Task 2 tests.
- `lineNumbers={false}` → the gutter columns and their header cells are both gone → Task 2 test.

### Task 1: `parseUnifiedDiff`

**Files:** Create `packages/design-system/src/components/DiffView/parseUnifiedDiff.ts`, `parseUnifiedDiff.test.ts`

**Interfaces — Produces:**

```ts
export type DiffLineKind = 'added' | 'removed' | 'context' | 'note';
export interface DiffLine {
  kind: DiffLineKind;
  text: string;
  oldNumber: number | null;
  newNumber: number | null;
}
export interface DiffHunk {
  oldStart: number;
  oldLines: number;
  newStart: number;
  newLines: number;
  section: string;
  lines: DiffLine[];
}
export function parseUnifiedDiff(diff: string): DiffHunk[];
```

`text` excludes the prefix character. `note` lines have both numbers `null`; added lines have `oldNumber` `null`; removed lines have `newNumber` `null`.

- [ ] **Step 1: Failing tests:**
  - the eocrm sample (`---`/`+++` + one hunk mixing all three kinds) gives the numbers line by line;
  - two hunks;
  - omitted counts default to 1;
  - `-0,0 +1,3` numbers new lines from 1;
  - CRLF;
  - a trailing newline adds no extra line;
  - `\ No newline at end of file` becomes a `note`;
  - preamble and unknown lines are ignored;
  - `''` and headers-only input give `[]`;
  - `section` carries the text after the closing `@@`.
- [ ] **Step 2:** `cd packages/design-system && npx vitest run src/components/DiffView` → FAIL.
- [ ] **Step 3:** Implement it as a single pass over the lines, with a regex for the hunk header: `/^@@ -(\d+)(?:,(\d+))? \+(\d+)(?:,(\d+))? @@ ?(.*)$/`.
- [ ] **Step 4:** Run → PASS.
- [ ] **Step 5:** Commit `feat(diff-view): unified diff parser (DS-94)`.
