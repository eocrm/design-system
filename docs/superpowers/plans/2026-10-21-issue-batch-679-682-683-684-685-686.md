# Issue batch #679 / #682 / #683 / #684 / #685 / #686 / #687 / #688 + Highlight waves — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship five issue fixes/features plus a Highlight redesign in one PR on `fix/tour-image-brandicon-tooltip`.

**Architecture:** Small isolated fixes (Tooltip, Image) first; then a shared SCSS wave mixin used by the Tour cue and the new overlay-based Highlight; then one shared overlay helper (`isTourHeld`) wired into every floating surface's dismiss paths, plus a CSS `:has()` rule that drops a surface containing the tour target under the scrim; finally DashboardCanvas reuses Highlight for section bands.

**Tech Stack:** React 19, TypeScript, SCSS modules, `@floating-ui/react-dom`, Vitest + Testing Library, npm workspaces.

**Spec:** `docs/superpowers/specs/2026-10-21-issue-batch-679-682-683-684-685-686-design.md`

## Global Constraints

- Tokens only in `.module.scss` — no raw colours/spacing/radii. Raw Tour/Highlight motion values live in the component's `*.tokens.scss` with a comment (as `--tour-pulse-duration` does today). Shared token values change only in `packages/design-tokens/src/tokens.json` (none expected in this plan).
- Components don't own layout (package CLAUDE.md Rule 4); overlays are positioned inline from TSX like Tour's Spotlight.
- Wave recipe (exact): 2 waves, cycle `2.2s`, easing `cubic-bezier(.2,.6,.4,1)`, second wave delayed `1.1s`, travel from the edge to `20px` outside, opacity `.9 → 0`, wave edge `2px` solid, inner gradient `inset 0 0 22px 5.5px` at 55% (Tour) / ~40–55% colour-mix (Highlight), corner radius grows by the travel.
- Tour wave colour: `var(--ring-on-scrim)` (white in both themes). Highlight colour: `var(--ring-accent)` default, `var(--color-palette-<color>-fg)` with `color`.
- Highlight steady ring: `1px` just outside the element. Reduced motion: static 1px ring (Highlight) / static 2px ring at the cutout edge (Tour); no waves, no fade.
- i18n `tour.clickHint` — en `'Click the highlighted element to continue'`, ru `'Нажмите на выделенный элемент, чтобы продолжить'`.
- `Image` `background?: 'muted' | 'none'`, default `'none'`.
- `DashboardCanvas` props `highlightedSectionId?: string | number`, `onSectionHighlightDone?: () => void`; no focus move.
- `DashboardWidget` `actionsReveal?: 'always' | 'hover'`, default `'always'`; hidden via opacity only (stays focusable, keeps width); revealed on `:hover`, `:focus-within`, an open `[aria-expanded='true']` action, and always under `(hover: none)`.
- Highlight overlay z: `--highlight-z: calc(var(--z-app-chrome) - 1)` (refines spec: below fixed app chrome so the top bar covers the ring); elevated (child inside a Modal/Drawer/Popover/Tour host via `useInOverlay`) → `var(--z-overlay-floating)`.
- #685 under-tour z: `calc(var(--z-tour) - 1)`.
- Tests sit beside the code they test (package CLAUDE.md "Test placement"). Run Vitest from `packages/design-system` (repo quirk).
- Commit messages: plain, no `Co-Authored-By`, no session link.
- Public API changes regenerate docs (`npm run build:docs`) and manifest (`npm run build:manifest`) from `packages/design-system`.

## Review Focus

1. **Highlight child that unmounts or re-renders mid-run** (list re-sort, row replaced) — the overlay must disappear with it, not linger at stale coordinates. → Task 6 test `removes the overlay when the child unmounts`.
2. **Two surfaces open at once while the tour points into one** (e.g. a Select open in the card body plus the menu the tour targets) — only the surface containing the target is held; the card-body Select still closes on an outside click. → Task 4 test `does not hold a surface the tour does not point into`.
3. **Tour closes while a held surface is open** — the `data-tour-current-target` marker must be removed on close so the surface dismisses normally afterwards. → Task 4 test `removes the current-target marker on close`.
4. **`highlightedSectionId` for a collapsed section** — the band (header) still exists and must highlight; nothing throws. → Task 7 test `highlights a collapsed section band`.
5. **Image `background="none"` while loading or errored** — skeleton and error tile keep their muted fill. → Task 2 tests.
