# Test & verification cost — first slice (#614) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut PR verification cost without weakening contracts: Node-by-default Vitest for `.test.ts`, a semantic public-API test instead of a source hash, and a parallel, path-selected Quality workflow behind an unchanged `Quality / check` status — measured before/after.

**Architecture:** Vitest `projects` split (`unit` = node, `dom` = jsdom) with per-file `@vitest-environment jsdom` opt-ins found by running. A Node `publicApi.test.ts` replaces the hash. `quality.yml` gets a `changes` job (shell `git diff` → boolean outputs via `scripts/ci-changes.sh`), six conditional jobs, and an always-run `check` aggregator.

**Tech Stack:** Vitest 4.1, Node 24 `node:test`, GitHub Actions, bash + jq.

**Spec:** `docs/superpowers/specs/2026-10-05-test-cost-design.md`

## Global Constraints

- Branch `chore/614-test-cost` (checked out). Never push, never open/modify PRs, never create issues — the controller does.
- Commit messages plain conventional; NO `Co-Authored-By`, NO session links, NO "Generated with" footer.
- The required status must remain `Quality / check`: the aggregator job id is exactly `check`.
- `release.yml` calls `quality.yml` via `workflow_call` and `needs: quality`; under `workflow_call` every stage runs.
- Keep action versions: `actions/checkout@v4`, `actions/setup-node@v4` (node-version `"24"`, `cache: "npm"`), `actions/setup-java@v4` (existing gradle cache config verbatim), `android-actions/setup-android@v3` (existing `packages: platform-tools`), `actions/upload-artifact@v4`.
- No new npm dependencies; no third-party path-filter action.
- Vitest runs from `packages/design-system` (`npx vitest run …`); `make test` from the repo root runs every workspace — read its EXIT CODE.
- Do not weaken any contract listed under the issue's "Do not reduce casually" (a11y, focus, contrast, packaging, token drift, release correctness).

## Review Focus

1. **A `.test.ts` that silently changes meaning in Node** (e.g. a guard `typeof window === 'undefined'` path now taken, so assertions run against a fallback) — expected: identical test count and the same assertions exercised. Pinned in Task 1 by comparing per-file test counts before/after.
2. **A PR touching only `docs/**`or`packages/playground/**`** — expected: `check` passes with library jobs skipped; never "pending forever". Pinned in Task 3 by script dry runs + the aggregator logic treating `skipped` as pass.
3. **A failing conditional job** — expected: `check` fails (not passes because the aggregator only saw `skipped`). Pinned in Task 3 by the aggregator's jq logic dry-run on synthetic `needs` JSON.
4. **A brand-new component dir missing from `src/index.ts`** — expected: `publicApi.test.ts` fails. Pinned in Task 2 by a probe.
5. **Release run (`workflow_call`)** — expected: all stages run. Pinned in Task 3 by the script dry run with a non-PR event.

- [ ] **Step 1: Write the script** — `scripts/ci-changes.sh`:

```bash
#!/usr/bin/env bash
# Decide which Quality stages a change needs (#614).
#   ci-changes.sh <event> <base-sha> <head-sha>   # CI: diff base...head
#   ci-changes.sh --files <list-file> [event]       # dry run on a file list
# Emits key=true|false lines to $GITHUB_OUTPUT (stdout when unset).
# Non-pull_request events (the release.yml workflow_call backstop) and any
# change to workflows / root tooling run EVERYTHING.
set -euo pipefail

out="${GITHUB_OUTPUT:-/dev/stdout}"
keys=(ds tokens compose playground package)

if [ "${1:-}" = "--files" ]; then
  files=$(cat "$2")
  event="${3:-pull_request}"
else
  event="$1"
  files=""
  if [ "$event" = "pull_request" ]; then
    files=$(git diff --name-only "$2...$3")
  fi
fi

emit_all() {
  echo "decision: $1 -> run everything" >&2
  for k in "${keys[@]}"; do echo "$k=true" >> "$out"; done
  exit 0
}

[ "$event" = "pull_request" ] || emit_all "event '$event' (release backstop)"

printf 'changed files:\n%s\n' "$files" >&2

FORCE='^(\.github/workflows/|scripts/ci-changes\.sh$|package\.json$|package-lock\.json$|\.npmrc$|\.nvmrc$|tsconfig[^/]*\.json$|\.prettierrc|\.prettierignore$|\.stylelintrc|playwright\.config\.|tests/|Makefile$)'
if grep -Eq "$FORCE" <<<"$files"; then emit_all "root tooling / workflow change"; fi

has() { grep -Eq "$1" <<<"$files" && echo true || echo false; }
LIB='^packages/(design-system|design-tokens)/'
{
  echo "ds=$(has "$LIB")"
  echo "tokens=$(has "$LIB")"
  echo "compose=$(has '^packages/design-tokens/')"
  echo "playground=$(has '^packages/(design-system|design-tokens|playground)/')"
  echo "package=$(has "$LIB")"
} | tee -a "$out" >&2
```

`chmod +x scripts/ci-changes.sh`. Note `tee -a "$out" >&2` writes decisions to the output file AND the log; when `$out` is `/dev/stdout`, the lines appear once on stdout and once on stderr — acceptable for dry runs.

#### Test placement (#614)

- **Cheapest environment wins.** Pure logic and static source analysis go in `*.test.ts` and run in Node (Vitest project `unit`). DOM/component semantics go in `*.test.tsx` (project `dom`, jsdom). - **No exact counts on extensible collections** (components, tokens, variants, registries) unless the number itself is a documented contract.
- **CI is path-selected** (`scripts/ci-changes.sh`, `.github/workflows/quality.yml`). A new expensive stage gets a `changes` flag and joins the `check` aggregator's `needs`.
