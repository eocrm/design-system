# Issue batch #673 / #674 / #675 / #678 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix fallback-less inline-only `var()`s library-wide (#673), EntityChip descender clipping (#678), add TreeView `onHoverChange` (#674), and add async `loadOptions` to OptionsPicker (#675).

**Architecture:** Three independent fixes plus one feature. The feature reuses Select's `useAsyncOptions`, moved to `src/components/_internal/`, and adds a pinned-selection snapshot and a label cache to `OptionsPicker.Content`. `onApply` gains a second argument with the selected options.

**Tech Stack:** React 18 + TypeScript, SCSS modules, Vitest (projects `unit` = Node, `dom` = jsdom), Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-20-issue-batch-673-674-675-678-design.md`

## Global Constraints

- One branch `fix/issues-673-674-675-678` off a freshly pulled `main` (`git checkout main && git pull` first).
- Library rules in `packages/design-system/CLAUDE.md` apply: tokens only, no layout props, i18n for every string (en + ru), JSDoc on every exported prop, Hard rule 10 for transient state.
- Commit messages: plain conventional commits, **no** `Co-Authored-By`, no session link, no "Generated with" footer.
- Run vitest from `packages/design-system` (`npx vitest run <path>`); read exit codes, never pipe gate commands through `grep`.
- Visual checks: playground on port **8090+**, never the default port; kill Playwright Chrome afterwards.
- Sync OptionsPicker and Select behaviour must not change (their existing tests are the guard).

## Review Focus

1. A selected value that no server answer and no `selectedOptions` ever labelled: the pinned row shows the raw value and `onApply` returns `{value, label: value}`, with no crash or blank row (test in Task 6).
2. A response for an old query arrives after a newer query's response: the stale response must not replace the list (test in Task 5).
3. Reopening the panel: a fresh fetch with `''` fires, and the previous session's unticked pinned rows are gone (test in Task 6).
4. Ticking a server row, or unticking a pinned row, doesn't move any row until the query changes (test in Task 6).
5. `labelEllipsis="start"` and `labelMaxWidth` chips still show an ellipsis after the overflow change (visual check in Task 8).
