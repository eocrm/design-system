# Dark categorical palette — design

**Date:** 2026-06-07
**Status:** Approved (brainstorm) → ready for implementation plan
**Package:** `@eocrm/design-system` (tokens + docs)
**Builds on:** the dark theme (`v0.1.21`, `src/styles/dark.scss`). This is the **fast-follow** that PR explicitly scoped out.

## Problem / goal

The dark theme (`dark.scss`) flips the ~40 color primitives + Badge/Tooltip tones, but deliberately left the **30-color categorical `--color-palette-*` set** (60 tokens — a `bg`+`fg` pair per color) at their light values. In dark mode those render as light chips on a dark page (the v0.1.21 Playwright sweep flagged the dashboard's palette-colored `IconTile` at `#deebff` as the one known out-of-scope artifact). This adds the dark variants so the categorical palette participates in dark mode like everything else.

The palette is used as a tinted chip/surface: `--color-palette-<name>-bg` is a surface, `--color-palette-<name>-fg` is the text/icon on it (consumed by `IconTile`, `Checkbox`, `OptionsPicker`, `Badge` palette tones, and the `PaletteDemo`).

## Decision (from brainstorming)

**Recipe — same hue, flip lightness, preserve saturation character.** For each color, take its **light `fg`'s hue + saturation** (the `fg` is the saturated representative of the color; the light `bg` is too washed out to read the hue from), then emit:

- **dark `bg`** = `hsl(H, min(S, 48%), 19%)` — a dark tint
- **dark `fg`** = `hsl(H, min(S, 90%), 78%)` — a light, vivid tint

The hue is preserved (red stays red); the lightness roles flip so the chip reads as a **dark tinted surface + light foreground** — identical in spirit to how `dark.scss` already renders Badge tones and `*-bg-subtle` surfaces. Saturation is **preserved** (capped, not forced), so deliberately-muted colors (`slate`, `stone`, `charcoal`, `taupe`) stay muted instead of turning vivid. The two caps (bg ≤ 48%, fg ≤ 90%) keep highly-saturated hues from producing a neon-dark bg or an over-bright fg.

The recipe is deterministic and was fit to the shipped dark Badge tones (dark bg ≈ L17–24% / moderate S, dark fg ≈ L69–82% / high S). It is used to **generate the concrete hex once**; the committed artifact is the literal hex below (not a runtime computation).

**Contrast:** every one of the 30 dark `fg`/`bg` pairs is **≥ 7.07:1** (WCAG AA needs 4.5:1 for normal text). These are CSS token values (not unit-testable in jsdom, same as the rest of `dark.scss`), so the contrast gate is the Playwright sweep (see Verification); the ratios are recorded in the table for reference.

## Mechanism

Add the 60 `--color-palette-<name>-bg` / `--color-palette-<name>-fg` overrides as **one block inside the existing `dark-tokens` mixin** in `packages/design-system/src/styles/dark.scss` (after the Badge/Tooltip block). Because the mixin is already emitted into both dark scopes (`:root[data-theme='dark']` and `@media (prefers-color-scheme: dark) { :root:not([data-theme='light']) }`), the palette flips under forced-dark and system-dark automatically — no new file, no new scope. The light values in `tokens.scss` are unchanged (light mode is untouched).

Component `var()`-aliases cascade for free: `IconTile`, `Checkbox`, `OptionsPicker`, and `Badge` palette tones all read `--color-palette-*` and flip with no component changes.

## Verification

- Gates: `make test`, `make build`, `make build-lib`, `make lint`, `npm run format:check`, `npm pack --dry-run`.
- **Playwright dark sweep of `/components/palette`** (the core check): force dark, then for every one of the 30 swatches read the computed `--color-palette-<name>-bg` / `-fg` and assert (a) the resolved value equals the dark hex (not the light value), (b) `fg`/`bg` contrast ≥ 4.5:1, and (c) no swatch bg is near-white (all channels < ~200). Confirm the 30 swatches read as coherent dark tinted chips.
- **Cross-check a consumer:** the dashboard's palette-colored `IconTile` (was `#deebff` in the v0.1.21 sweep) now renders a dark tile.
- Light mode unaffected: spot-check `/components/palette` in forced light still shows the original light swatches.
- Library Rule-8 review loop.

## Non-goals

- The **light** palette (`tokens.scss`) — unchanged.
- TS surface (`PaletteColor`, `PALETTE_COLORS`, palette helpers) — unchanged.
- The **avatar** identity palette (`--color-avatar-*`) — theme-independent by design; out of scope.
- Any runtime color computation — the dark hex is committed literal values (generated once by the recipe).
