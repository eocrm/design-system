# Issue batch #727 #736 #737 #738 #739 — design

Task: DS-7. These are five open consumer issues (from the eocrm web app), shipped on one branch and one PR.
Each issue body is the problem statement. This doc records the decisions the user made on 2026-11-03.

## Decisions

### #736 LinkCard `as="button"`

A button-rendered LinkCard has to fill its container the way the `<a>` form does. Two UA defaults currently stop that:

- **Width.** A block-level `<button>` still shrink-wraps to its content.
- **Text alignment.** The UA styles button text with `text-align: center`.

**Fix.** Add `width: 100%` and `text-align: start` to `.linkCard`.

- `width: 100%` is allowed under Hard rule 4.
- `text-align: start` is logical, so it is RTL-safe, and it matches the `<a>` form.

This is a bug fix with no API change.

### #738 Timeline

**New default, no prop.** The node centres on the item's **first line** rather than on a fixed box beside top-aligned content. Every existing timeline's node moves by a few px. The CRM is the only consumer.

**Mechanism.** CSS only, left to the builder. Candidates:

- pad the content's block-start by `(node-size − first-line-height) / 2`, using a component token for the first-line height;
- or an equivalent grid alignment.

**Constraints.**

- It must hold for both default and `compact` sizes.
- It must hold for the documented common header: `Text size="sm"`, with or without an inline `PersonDisplay`.
- It must not break the connector line.
- Verify the geometry in a real browser with Playwright; jsdom can't measure it.

### #737 DashboardCanvas

A resize, move or section gesture must never start or leave a text selection. Some browsers and OSes start a selection on `pointerdown`, before `data-dragging` (which sets `user-select: none`) is applied.

**Fix.**

- Call `preventDefault()` on `pointerdown` for the **resize handles** and the **section grip**. Both are content-free.
- For **move** (whose `pointerdown` deliberately doesn't preventDefault so body clicks pass through), suppress `selectstart` while a gesture is armed or active, and clear any existing selection when the drag arms.

This is a bug fix with no API change.

### #727a List

Add `variant="plain"` to `ListVariant`, so it becomes `'bullet' | 'number' | 'plain'`.

- Renders `<ul>`/`<li>`, keeping list semantics, with no marker and the DS `gap`.
- `numberStyle` and `size` have no effect on `plain`, and the JSDoc says so.

### #727b Text alignment

- **Default changes from forced `left` to inherit.** No align class is applied unless `align` is passed.
- **New logical values.** Add `'start' | 'end'` to `TextAlign`. The existing `'left' | 'center' | 'right'` keep working.
- **Audit risk.** A `Text` inside a centred parent (e.g. a raw `<button>`) would now inherit centring. Audit library usages and pin `align="start"` wherever the forced-left default was load-bearing.
- **Expected result.** `Table.Cell align="end"` values align without extra props.

### #739 RichText

Add `onImageActivate?: (image: { src: string; alt?: string }, trigger: HTMLElement) => void`.

- **When set.** Each ready inline image attachment renders inside a DS-owned trigger:
  - it is a native `<button type="button">`;
  - its accessible name combines `alt` (or the attachment name) with an i18n "Open image" label in both `en` and `ru`, using `||` fallbacks for accessible names per `docs/accessible-names.md`;
  - it has the library focus ring;
  - Enter and Space activate it natively.
- **What the callback receives.** The trigger element, so the consumer can restore focus after closing a Lightbox.
- **When unset.** Markup stays exactly as today.
- **Images inside links.** Attachments are blocks and are never inside links, so there is no link interaction.

## Non-goals

No new components. No `renderImage`. No `nodeAlign` prop. No `marker` prop.
